# Spec 01 — Fix: backend dev server crash on start

Date: 2026-10-17
Command under test: `npm run dev:backend`

## Reported problem

Running `npm run dev:backend` compiled with "Found 0 errors" but then crashed:

```text
Error: Cannot find module 'D:\...\scratch\backend\dist\main'
    at Module._load ...
    code: 'MODULE_NOT_FOUND'
```

## Root cause

1. `backend/nest-cli.json` has `"deleteOutDir": true` — the Nest CLI deletes `backend/dist`
   on every start of `nest start --watch`.
2. The TypeScript incremental build cache lived outside `dist` in
   `backend/tsconfig.build.tsbuildinfo` (enabled by `"incremental": true` in `backend/tsconfig.json`).
3. After `dist` was deleted, TypeScript saw the cache as "up to date", skipped emitting,
   and `dist/main.js` was never written. Nest then tried `node dist/main` and crashed.

## Changes made

### 1. `backend/tsconfig.build.json`

Moved the incremental build cache inside `dist`, so it is deleted together with the
output folder and a full compile is forced on every fresh start.

```diff
 {
   "extends": "./tsconfig.json",
   "compilerOptions": {
-    "rootDir": "./src"
+    "rootDir": "./src",
+    "tsBuildInfoFile": "./dist/tsconfig.build.tsbuildinfo"
   },
   "include": ["src"],
   "exclude": ["node_modules", "test", "dist", "**/*spec.ts"]
 }
```

### 2. Stale artifacts removed

- Deleted stale `backend/tsconfig.build.tsbuildinfo` (old cache location).
- Deleted the emptied `backend/dist` folder so the next build starts clean.

No application source code was changed.

## Verification

1. `npm run dev:backend` now completes the full startup:
   - `prisma generate` → Prisma Client v6.19.3 generated.
   - Compile: `Found 0 errors. Watching for file changes.`
   - `[NestApplication] Nest application successfully started` (listens on port 3000).
2. Routes mapped at boot:

   ```text
   AppController      {/api}                GET /api
   ProductsController {/api/products}       GET /api/products
                                            GET /api/products/categories
                                            GET /api/products/deals
                                            GET /api/products/:id
   ```

3. `npx prisma migrate status` (from `backend/`) →

   ```text
   2 migrations found in prisma/migrations
   Database schema is up to date!
   ```

4. Live smoke test: `GET http://localhost:3000/api/products` returned
   `{ "products": [], "total": 0 }` (HTTP 200 — DB reachable, no seed data yet).

## Result

`npm run dev:backend` runs without errors. Watch mode is active and hot-reloads on
file changes; the incremental build now rebuilds fully on each fresh start because the
cache file is stored inside the deleted `dist` folder.
